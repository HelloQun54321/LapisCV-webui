# Agent 协作指南

工作台使用本地 Markdown 保存简历，网页可视化编辑与外部文件编辑共享同一份内容。支持本地文件读写的 AI Agent 可以读取简历和岗位 JD，整理经历、修改表达、调整内容顺序；修改完成后，在网页中审阅内容、微调排版，并通过实际 PDF 校样确认结果。

Agent 通过读写项目文件参与工作流。需要在所使用的 Agent 工具中打开项目目录；模型、账户和工具权限由该工具配置。

## 内容与版本的位置

| 文件或目录 | 用途 |
|---|---|
| `resumes/_master/resume.md` | 母版，持续维护完整经历与基础资料 |
| `resumes/公司-岗位/resume.md` | 针对该岗位修改的独立子版 |
| `resumes/公司-岗位/jd.md` | 岗位要求原文 |
| `resumes/公司-岗位/meta.md` | 公司、岗位、投递状态、日期与备注 |
| `resumes/公司-岗位/.webui.json` | 该子版的模板选择及相关设置 |

子版创建时完整复制来源简历，之后独立保存。母版可继续积累经历，岗位子版按 JD 选择重点；某一子版的修改不会同步到母版或其他子版。

文件名和数据约定见 [命令行指南](../README-cli.md)。个人使用数据已忽略入公开 Git；备份与隐私说明见 [数据与隐私](privacy.md)。

## 推荐协作流程

1. **保存当前编辑**：在网页中维护母版并保存。较大的内容调整前，可在「更多操作 → 历史版本」保留一个命名版本。
2. **创建岗位子版**：使用网页「新建投递」，填写公司、岗位与 JD。也可在仓库根目录运行 `npm run new -- "公司名" "岗位名"`，再填写该目录的 `jd.md`。
3. **给 Agent 明确范围**：在 Agent 中打开项目目录，指定本次投递目录，要求读取 `resume.md` 与 `jd.md`。开始前阅读 [代理入口](../AGENTS.md) 和 [简历渲染与内容约束](resume-constraints.md)。
4. **按岗位修改内容**：在子版中调整经历重点、表达和顺序，保留现有样式、图片路径与结构。需要补充或确认的事实应单独列出，便于审阅。
5. **回到网页确认**：选择该子版查看修改，继续编辑文字或调整排版；使用「与当前母版比较」核对差异，再打开「分页校样」检查实际 PDF。
6. **保存投递定稿**：准备发送时保留定稿，存下当时的 PDF、简历、JD 与投递信息。后续继续修改子版时，该定稿保持原样。

每一步都可由使用者接手。Agent 的内容修改写入本地文件，网页编辑保存到同一份文件；源码模式也可用于手工修改 Markdown、HTML 与自定义 CSS。

## 示例任务

将下列 `resumes/公司-岗位/` 替换为已创建的实际投递目录：

```text
请先阅读 AGENTS.md 和 docs/resume-constraints.md。

本次只调整 resumes/公司-岗位/resume.md。
读取该目录的 jd.md，结合简历已有经历，调整内容重点、条目顺序和措辞。
保留母版及其他投递版本，保留现有样式、头像和图片路径。
需要补充或确认的事实请单独列出。
完成后说明主要改动，以及哪些内容需要在网页和 PDF 校样中复核。
```

## 文件同步与冲突

网页可见时，约每 8 秒检查当前文档的外部修改。没有未保存编辑时，会加载最新文件；若网页仍有草稿，会提示版本冲突，并提供下载草稿、加载最新和明确覆盖的选项。

外部编辑前先保存网页，完成后再继续纸面编辑。外部文件的重新加载会重建当前编辑会话；已保存内容可通过文件历史恢复，外部修改不加入当前浏览器的文字撤销栈。大幅调整前应先保留命名版本或私下备份。

工作台的本地保存与 Agent 的数据处理方式分别由工作台和所使用的 Agent 工具决定，使用外部工具时应确认其文件访问和数据设置。
