# 使用与自定义指南

本指南介绍简历编辑、版式调整、投递管理、备份，以及通过源码自定义工作台的方法。网页默认使用可视化编辑，也可切换 Markdown 源码。

首次安装从 `examples/` 初始化示例母版。在网页或 `resumes/` 中填写个人资料，照片通过网页上传到 `assets/uploads/`。`examples/` 和 `assets/avatar.png` 用于分发示例，应保留虚构内容与占位头像。

## 与 Agent 交替编辑

可视化编辑和文件编辑共享本地 Markdown。支持本地文件读写的 AI Agent 可以读取简历与 JD，修改内容后在网页中查看结果，再通过纸面工具调整字号、间距和头像。开始外部修改前先保存网页中的编辑；页面可见且没有未保存内容时，约每 8 秒同步当前文件的外部修改，存在草稿时提示冲突。

岗位定向修改应放在独立子版中，母版持续保留完整经历。文件路径、协作步骤与示例任务见 [Agent 协作指南](agent-workflow.md)。

## 日常改简历

左侧是两层导航：最左的图标栏切换简历、归档与回收站，旁边显示搜索和投递列表。搜索框旁的筛选按钮可展开状态、跟进日期与列表分组；已选筛选会显示摘要，点击摘要可重新展开。顶部菜单可收起列表，保留图标栏。

图标栏左下角的月亮／太阳按钮切换日夜模式。日间使用白灰配色，夜间使用黑灰配色，简历纸面也显示深底浅字。其下的「外观与字体」可选择系统字体或思源黑体，以及标准 14 px、舒适 15 px、大字 16 px；设置会在当前浏览器自动记住。这里只调整工作台，简历的字体、字号仍在「排版」或选中文字后的工具栏里修改。

夜间模式不修改简历保存的颜色与字体，导出 PDF / Word 保留原始打印配色。实际 PDF 校样默认也使用夜间阅读颜色，照片保留原色；点击「打印配色」可检查导出文件的原始颜色，再点击返回夜间阅读。

启动服务后打开 http://127.0.0.1:3210，选择左侧的母版或投递版本。在「编辑」中点击姓名、标题、正文或经历日期，直接输入和删除；选中文字后使用工具栏设置字体、字号、颜色、加粗、斜体、下划线、对齐与列表。Ctrl+Z 撤销、Ctrl+Y 重做，停止输入约 1 秒后自动保存。

点击「排版」按需展开右侧「排版与结构」，工作台记住面板和各节的开合状态。选中头像、普通图片、装饰横线或表格时，会展开对应设置，面板顶部显示当前选区。这里可插入章节、经历、分页符、装饰横线、图标、头像、普通图片、表格和链接。整份简历的字号、字体、行距、章节间距、强调色与四侧页边距可直接修改，数值支持小数。选中文字后的字号框可直接输入，例如 11.3pt。点击段落后，可单独设置段前段后间距和缩进。章节与经历可用箭头移动、点击垃圾桶删除；经历旁的移入图标可移到其他章节末尾。这些操作都可以撤销。左上角菜单可收起简历列表。

需要编辑 HTML、注释或自定义 CSS 时，点击「源码」。宽窗口并排显示源码与预览；窄窗口通过「查看预览 / 返回源码」切换，两种视图都使用完整可用高度。未修改的原始内容保留原样，自定义 ID、类名、图片宽高和常见 HTML 属性在图形编辑后继续保留。不认识的自定义结构仍显示并保存，可双击打开局部 Markdown／HTML 编辑框，也可在源码模式修改。

同一份简历在当前网页会话中切换源码与可视化模式，会保留撤销记录；源码修改作为一步加入撤销。替换或删除图片、调整对象属性也支持撤销。刷新网页、加载另一份简历或恢复文件历史后，使用「历史版本」恢复此前文件；浏览器会话中的撤销不跨刷新保留。

## 选择简历版式与调整个人信息

打开「排版 → 整份简历排版」，在「简历排版」中选择以下三种布局。名称描述排列方式；正文与标题字体可以在同一面板另行调整。

| 简历排版 | 排列方式 |
|---|---|
| 居中标准 | 姓名居中，电话、邮箱、链接横排，求职意向另起一行，头像靠右 |
| 左对齐标题 | 姓名和基本信息靠左，姓名标题较大，正文单栏 |
| 横向名片 | 头像与姓名、基本信息组成横向页头，正文通栏 |

切换版式保留当前文字、原有自定义 CSS、单个头像的尺寸与偏移。已有居中与左对齐版式的保存记录继续有效；若原有 CSS 明确设置了对齐、字号或头像位置，它会继续覆盖模板默认值。

三种版式的正文均采用 1.5 行距；居中标准与横向名片默认为 10pt，左对齐标题默认为 9.5pt。横向名片采用紧凑页头与通栏正文。页数由实际内容与设置决定，用「分页校样」检查。旧版本的侧栏名片与章节分栏记录会回退到居中标准，简历内容继续保留；读取时不改写原始文件。

在「排版 → 个人信息布局」可设置姓名和基本信息的左／中／右对齐、头像靠左或靠右、基本信息一栏或两栏、基本信息字号和行距、姓名下方间距、信息块下方间距，以及信息块水平／垂直偏移。「跟随模板」让对齐和头像方向采用当前模板的默认值；其他已设置的参数继续保留。基本信息指姓名下方、第一条二级章节标题之前的联系方式、求职方向等内容。

「联系方式排列」与文字对齐分开设置：三种版式均默认横排，空间不足时自然换行。「跟随模板」恢复当前版式的默认排列；也可明确选横排或竖排，并设置联系方式间距。只调整页头的第一段联系方式，求职意向保留单独的段落。源文件中的换行、空格、电话、邮箱和链接仍然保留；这些显示规则不会重写原文。

居中与左对齐版式会根据头像实际宽度为联系方式留出空间；头像位置可继续微调。网页及 PDF 使用这些规则；Word 仍按原有源段落转换，暂未复现联系方式排列。

头像的左右选择在模板指定的页头内生效；需要精细移动、缩放和裁剪时，点击头像后使用「头像尺寸、位置与裁剪」。全局设置与单个对象设置都可撤销。网页与 PDF 使用同一套结构；横向页头目前用于网页与 PDF，Word 导出仍使用原有段落布局。

## 头像、图片和横线

点击纸面上的头像，会出现顶部移动手柄和右下角缩放手柄。拖动时显示轮廓，松开后应用；一次拖拽是一条撤销记录。在「头像尺寸、位置与裁剪」中可输入宽、高和水平／垂直偏移，小数毫米也可使用。水平偏移正值向右、垂直偏移正值向下；偏移相对于图片原来的排版位置，不是页面绝对坐标。四个方向按钮每次移动 0.1mm，±5% 按钮等比例缩放。

移动头像或普通图片时，默认启用「智能对齐辅助线」：靠近纸面的水平／垂直中线、正文边缘或姓名、章节标题、其他图片的边缘与中线时，显示蓝色虚线及对齐目标，并在约 5 个屏幕像素内轻微吸附。夜间使用更亮的蓝色。纸面缩放后仍按屏幕距离判断。按住 **Alt** 可暂时取消吸附，保留对齐提示；按 **Esc** 取消本次拖动。松开应用位置后，一次撤销即可恢复。右侧排版面板底部可关闭「智能对齐辅助线」，该偏好会在本机记忆。

辅助线只在移动预览中显示，不写入简历源码，也不进入 PDF 导出。当前用于头像及普通图片的移动手柄；缩放手柄和毫米输入仍按原来的精细控制方式工作，不吸附。这里提供自动对齐参考，暂未提供从标尺拉出固定参考线的功能。

「锁定宽高比例」默认开启；改宽度时高度联动，也用于拖拽缩放。关闭后可以分别调整照片框的宽高。水平、垂直裁剪滑块只改变框内取景，不移动整个图片框。选中多个头像中的某一个后，设置、替换和移除只针对它；未选中头像时操作第一个头像。替换会保留尺寸、偏移和其他原有属性，原文件仍保留。

普通图片使用「普通图片」上传。在纸面上选中图片后可拖动手柄，在「普通图片」面板输入尺寸与偏移、替换或删除。输入框的宽、高可分别修改；拖拽缩放的比例锁与头像共用。

「横线样式与位置」可设置粗细、长度、文字距离、水平／垂直偏移、颜色和线型。先点击章节标题或该章节内容，默认只影响当前章节；选择「所有章节」再改某项，会将该项应用到全部章节。插入的「装饰横线」是独立对象，点击后使用同一面板调整，可隐藏、删除或撤销；它不会让 PDF 换页。「插入分页符」才会强制换页。

基础表格可以直接点击单元格输入，使用「表格行列」按钮在末尾增减行列。已有合并单元格会保留，但暂不支持在网页里合并／拆分单元格或对这种表格增减行列。复杂 WPS 浮动文本框、分栏和对象图层尚未提供对应工具。

链接可直接点击链接文字，再点「编辑链接」，会回填文字和原网址；支持 http、https、mailto、tel，也可以「取消链接」而保留文字。修改网址时保留原文字格式。

编辑时使用连续 A4 宽度纸面。点击纸面上方「分页校样」会先保存当前内容，再用本机浏览器生成实际 PDF，直接在网页中逐页显示；可切换页码、缩放、更新校样与下载。这里的分页、字号和头像就是导出文件的实际版式。点击「返回编辑」继续输入，撤销记录和文字选区仍保留。分页符在编辑时显示为虚线提示，在 PDF 中从下一页继续内容。校样只供检查，不直接编辑；调整内容或排版后重新校样。

桌面顶部第一行是当前简历、内容导航、保存、更多和导出；第二行根据编辑、源码或 PDF 校样模式显示对应工具。缩放与适应宽度在第二行右侧；简历版式在「排版 → 整份简历排版」中选择。在源码模式点击排版会回到纸面编辑并打开面板。保存按钮直接显示已保存、尚未保存或保存失败，仍可点击或使用 Ctrl+S 手动保存。

「分页校样」旁显示上次校样的实际页数，悬停可查看有效状态、时间和版本摘要；未校样时不显示占位说明。简历内容、主题或本地样式与素材变化后显示「需更新」；仅修改 JD 或投递日期不影响 PDF 校样。再次校样或导出 PDF 后更新记录。PDF 校样中的页码与总页数集中在工具栏，编辑纸面长度不表示实际 PDF 页数。

粘贴默认保留常见的加粗、字号、颜色和对齐，会清理外部页面布局样式，并把字体映射到本地字体。右侧取消「保留粘贴格式」，或使用 Ctrl+Shift+V，即可按纯文本粘贴。基础表格可编辑，但复杂 WPS 布局不会成为完整 Word 对象。「清除文字样式」清除选中的加粗、字号、颜色等文字样式，保留标题层级、列表和段落结构。

面板把全局排版设置写入当前 Markdown 的 `<style data-webui-layout>` 中，继续使用同一条 PDF 渲染链，保留你原有的 `<style>`。单个图片和横线的属性写在该对象的 HTML／CSS 中。「重置全局排版」只移除面板生成的全局设置，不删除原有自定义 CSS 或单个对象设置。字体菜单使用随项目提供的字体；思源宋体目前随附的是粗体字体文件。

母版保存完整经历。针对某个岗位删改时，先新建投递版本，再修改子版。「岗位 JD」和「投递信息」分别编辑原文、公司岗位、状态、投递日期、下次跟进与备注。子版纸面上方「对照 JD」可打开右侧可编辑的 JD 参考，边读岗位要求边调整简历；JD 使用同一套自动保存。更多操作中「与当前母版比较」展示正文差异，也可切到完整 Markdown／HTML 源码，并展开 JD、主题和投递信息差异。参考的是现在的母版；比较包含当前草稿，不会改动母版或子版。

「岗位 JD」使用独立原文编辑区，显示字数和自动保存；「导入」可读取文本或 Markdown，「下载原文」输出 TXT。「投递信息」直接显示表单，保存使用顶栏按钮或自动保存。

侧栏默认显示未归档投递，可选择「已归档」或「全部记录」，同时按状态与跟进日期筛选、按公司或状态分组；选择会在当前浏览器记住。「到期跟进」包括今天及更早的日期，「未来 7 天」包括今天至 7 天后的日期；已归档、已拒和已关闭的投递不计入。这些提示显示在工作台里，不会发送系统通知。

投递卡片右侧的「⋯」打开管理菜单，可编辑投递信息、复制、归档或删除；顶栏「更多操作」也提供归档和删除。归档用于收起已经结束、仍需保留的投递，简历、JD、投递状态、历史和定稿全部保留，可在已归档列表中查看、编辑或取消归档。「已关闭」是投递状态，与归档相互独立；修改其中一个不会自动修改另一个。

删除用于清理不再需要的投递，确认后移入回收站。点击侧栏「回收站 → 恢复」即可找回，包括原来的归档属性、历史和定稿。母版不能归档或删除。

头像使用上传入口；不想显示头像时，删除 Markdown 里的 `<img class="avatar" ...>` 行即可，原图片文件仍然保留。

误改后打开「更多操作 → 历史版本」恢复。自动历史保留最近 40 次；点击「保留当前版本」填写名称，或给已有历史命名，可长期保留关键节点，超过 40 次保存也不清理。清空名称后重新作为自动历史管理。恢复先显示参考版本与当前编辑的差异，再点「恢复参考版本」确认；当前编辑会先保存，并在恢复前留历史。关闭自动保存时，使用 Ctrl / ⌘ + S 手动保存。有其他窗口或外部编辑器同时改文件时，工作台会提示处理版本冲突。

## 保存投递定稿与完整备份

准备发送简历时，在子版的「更多操作 → 保存投递定稿」填写名称和日期，生成实际 PDF 并长期留档。档案同时保存当时的简历、JD、主题和投递信息，附页数、版本与 PDF 校验摘要。后续修改、重新导出和服务重启都不会替换这份定稿；「投递定稿档案」可下载原始 PDF、查看快照或与当前编辑比较。把子版移入回收站后恢复，其历史和定稿仍能使用。留档不自动改状态；实际发送后，在投递信息中记录状态与日期。

「更多操作 → 完整备份工作台 ZIP」打包源码、全部母版与子版、PDF、JD、投递信息、字体与素材、自动历史、命名版本、定稿和回收站，附文件清单和恢复说明。先保存其他窗口中的编辑；当前窗口在打包前自动保存。ZIP 不包含 Git 提交历史、凭据、依赖、浏览器未保存草稿和临时文件。

迁移时解压到新的文件夹，安装 Node.js 22.12 或更新版本与 Chrome / Edge，在新目录执行 `npm ci`，再双击「启动简历工作台.cmd」。依赖和前端构建文件会自动生成，原有数据与档案继续使用。

## 在网页里调整单份简历的排版

可在 Markdown 中添加或修改 `<style>`，预览和 PDF 都会使用它。以下是独立示例；如果已有 `<style>`，优先修改已有对应规则，避免后面的旧规则又覆盖你的设置：

```html
<style>
  body {
    --text-size: 10.5pt;
    --line-height: 1.6;
    --h1-size: 18pt;
    --h2-size: 12pt;
    --color-accent: #607fa6;
  }

  h2 { margin-top: 3mm !important; }
  .avatar { width: 18mm; height: 24mm; }
</style>
```

这样可以调整文字大小、行距、标题、章节间距、颜色、头像尺寸，以及你熟悉的其他 CSS 规则。样式只影响当前这份简历。手工分页是在单独一行写 `<hr>`。点击「分页校样」检查实际分页。

正文和标题有独立字体变量 `--text-font` / `--title-font`。使用新的字体名称时，还要配置对应的 `@font-face` 和本地字体文件；只改一个不存在的名称会触发字体检查。项目内置的主题和字体可以直接使用。

## 更改网页本身或共享主题

界面动作图标使用本地 Lucide SVG，入口是 `web/icons.js` 和 `web/ui-icons.svg`；来源与许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。常驻界面只显示操作名称、必要状态和对象范围，进阶说明使用悬停提示、可展开内容或本指南。简历正文图标与工作台图标分别维护。

用 VS Code 或你喜欢的编辑器打开整个项目根文件夹（即包含 `package.json` 的目录）。文件用途如下：

| 想调整什么 | 编辑哪里 | 查看方式 |
|---|---|---|
| 这份简历的文字与单独样式 | 网页 Markdown，或 `resumes/对应目录/resume.md` | 网页实时预览；外部编辑约 8 秒后同步 |
| 各版式的字体、字号、行距、颜色与排列 | `assets/styles/classic.css` / `serif.css` / `banner.css` | 页面刷新或重新触发预览，再生成 PDF 核对 |
| 所有版式共用的章节、列表、头像规则 | `assets/styles/main.css` | 页面刷新或重新触发预览 |
| 版式名称与个人信息、章节的显示角色 | `web/resume-layout.js` | 编辑与预览共用；显示属性不写回内容 |
| 网页配色、侧栏、顶部高度、编辑区宽度 | `web/app.css` / `web/workflow.css` | 保存后刷新网页 |
| 网页按钮、结构、文案 | `web/index.html` | 保存后刷新网页 |
| 按钮行为、自动保存时间、快捷键 | `web/app.js` | 保存后刷新网页 |
| 定稿、版本比较、JD 对照、备份和跟进筛选 | `web/workflow.js` / `web/diff.js` | 保存后刷新网页 |
| PDF 页边距、渲染流程 | `src/render.mjs` | 重启服务，生成 PDF 核对 |
| API、上传限制、存储与历史规则 | `src/server.mjs` / `src/store.mjs` | 重启服务并验证功能 |
| 公开空白模板 / 本机副本 | `examples/template.md` / `resumes/_template.md` | 首次安装复制，修改本机副本不会更改公开模板 |

`web/app.css` 的语义颜色变量控制日夜主题，布局规则控制双层导航与编辑空间；`web/visual-editor.css` 保存格式和排版面板样式，`web/workflow.css` 保存工具栏、筛选、JD 参考与比较对话框。`web/appearance.js` 管理外观偏好与纸面屏幕样式。优先直接修改对应规则，避免不断叠加覆盖后难以维护。字体、图标和占位头像均随项目提供。

修改前端前先保存网页中正在编辑的内容，再刷新；修改 `web/visual-editor.js` 或 `web/pdf-proof.js` 后运行 `npm run build:web` 重新打包，再刷新。依赖、编辑器、PDF 校样阅读器和字体都打包到本地，日常使用不需要访问 CDN。安装依赖和启动服务时会自动打包。修改服务端代码后重启；开发时可运行 `npm run dev` 自动重启服务端。网页不会热重载前端代码。

## 开发版本记录

简历编辑使用文件保存和历史恢复。程序、样式或文档的开发改动使用 Git 记录；完成一组改动后，可在仓库根目录执行：

```powershell
cd LapisCV-webui
npm run iterate -- "调整工作台配色和编辑区宽度" --files web/app.css
```

一次改多个文件，把文件名逐个列在 `--files` 后面。命令会验证、递增版本、写变更记录、自动提交并创建版本标签。查看版本记录：

```powershell
git log --oneline --decorate -10
git tag --list "v*"
git status --short
```

公开 Git 用于程序与虚构示例的版本管理。整个 `resumes/`、`assets/uploads/`、`.local/` 以及 PDF、DOCX、ZIP 不入 Git。个人使用数据通过网页历史与私下 ZIP 备份保存；备份含真实资料，不要上传到公开仓库或问题附件。发布前执行 `npm run check:public`，并人工核对截图和新增示例。详细说明见 [隐私与发布](privacy.md)。
