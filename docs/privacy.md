# 数据与隐私

简历、照片和投递记录保存在本机文件中。仓库提供虚构示例和通用占位头像，个人使用数据与程序源码分开保存，默认不提交到 Git。

## 首次使用与保存

`npm ci` 会把 `examples/resume.md` 复制到私有的 `resumes/_master/resume.md`，把 `examples/template.md` 复制到 `resumes/_template.md`。直接启动服务也会检查并初始化缺失的母版。已有文件永不覆盖；更新示例和重新安装依赖不会替换你的简历。

在网页或 `resumes/` 中填写个人信息。`examples/` 是公开示例，修改它会成为源码变更，请保持虚构内容。网页保存不会修改 `examples/`。

| 位置 | 内容 | Git 策略 |
|---|---|---|
| `examples/` | 虚构示例与空白模板 | 公开入库 |
| `resumes/` | 母版、投递子版、JD、meta、设置、导出 | 全部忽略 |
| `assets/uploads/` | 上传的个人头像和图片 | 全部忽略 |
| `.local/` | 历史、定稿 PDF、回收站、日志、校样、临时文件 | 全部忽略 |
| `.env`、`.env.*` | 本机凭据配置 | 忽略（虚构的 example / sample 文件除外） |
| PDF、DOCX、ZIP、BAK | 导出和完整备份 | 忽略 |

头像请通过网页上传，或自行放在 `assets/uploads/` 后引用。`assets/avatar.svg` 和 `assets/avatar.png` 是公开的占位素材，不要用真实照片覆盖它们。姓名、电话、邮箱、教育、任职、作品链接及备注都属于使用数据，不应移进示例或源码。

## 发布前检查

```bash
npm run check:public
```

检查 Git 暂存区和全部分支、标签可达的提交，拒绝个人数据目录、备份、常见 GitHub 令牌和私钥。提交钩子也检查暂存区；即使用 `git add -f` 强制加入私有目录，也会被拦截。脚本只报告文件名，不打印疑似凭据。

检查不能识别所有真实姓名、普通文本中的联系方式、图片内容或所有凭据格式。新增示例、截图和二进制素材仍须人工核对。公开提交作者会显示 Git 用户名和邮箱；可以在仓库配置 GitHub 提供的 noreply 邮箱。

`.gitignore` 只影响尚未跟踪的文件，不能删除已经存在的 Git 历史。若曾提交个人数据，请先停止推送，检查历史，采用干净的新仓库或专门的历史清理流程；泄漏令牌应同时撤销。不要将个人工作台的旧 `.git/` 复制进公开源码目录。

## 备份与问题反馈

「完整备份工作台 ZIP」包含真实母版、子版、JD、个人图片、历史、定稿和回收站，用于私下迁移或恢复。**备份 ZIP 不属于公开发布包，不要上传到 GitHub Release、Issue 或公开网盘。** Git 源码备份不包含这些个人使用数据。

反馈问题时使用虚构简历复现，检查截图、日志和附件中的姓名、电话、邮箱、头像、公司、岗位与本机路径。网页服务默认只监听本机，不会把简历上传到 GitHub；推送代码由使用者自己执行。
